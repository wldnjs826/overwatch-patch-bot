# 오버워치 패치 노트 → 디스코드 자동 알림

블리자드 한국어 패치 노트 페이지를 15분마다 확인합니다.

- 최신 패치가 새로 올라오면 디스코드 웹훅으로 전송
- 같은 날짜의 최신 패치 본문이 수정돼도 다시 전송
- 긴 개발자 설명은 제외
- 패치 항목, 역할군, 영웅, 기술명, 수치 변경 중심으로 정리
- 중복 전송 방지를 위해 `state.json`에 최신 본문 해시 저장
- 개인 PC를 켜둘 필요 없이 GitHub Actions에서 실행

## 1. 디스코드 웹훅 만들기

1. 알림을 받을 디스코드 서버에서 원하는 텍스트 채널을 엽니다.
2. `채널 편집 → 연동 → 웹후크 → 새 웹후크`로 이동합니다.
3. 이름과 채널을 정한 뒤 `웹후크 URL 복사`를 누릅니다.
4. 웹후크 URL은 비밀번호처럼 취급하며 다른 사람에게 공개하지 않습니다.

## 2. GitHub 저장소 만들기

1. GitHub에서 새 저장소를 만듭니다.
2. 이 폴더 안의 파일을 저장소 최상단에 업로드합니다.
3. 공개 저장소로 만들어도 되지만 웹후크 주소는 코드에 직접 넣지 않습니다.

필수 구조:

```text
.github/workflows/check-patch.yml
monitor.py
requirements.txt
state.json
```

## 3. 웹훅 주소를 GitHub 비밀값으로 등록

저장소에서 다음 경로로 이동합니다.

`Settings → Secrets and variables → Actions → New repository secret`

- Name: `DISCORD_WEBHOOK_URL`
- Secret: 앞에서 복사한 디스코드 웹후크 URL

## 4. 최초 실행

1. 저장소의 `Actions` 탭을 엽니다.
2. 왼쪽에서 `Overwatch patch monitor`를 선택합니다.
3. `Run workflow`를 눌러 수동 실행합니다.
4. 정상이라면 현재 최신 패치가 디스코드 채널에 올라옵니다.
5. 이후에는 15분마다 자동 확인합니다.

## 설정 변경

`.github/workflows/check-patch.yml`에서 바꿀 수 있습니다.

### 확인 주기

현재:

```yaml
- cron: "*/15 * * * *"
```

예시:

```yaml
- cron: "*/30 * * * *"  # 30분마다
- cron: "0 * * * *"     # 1시간마다
```

### 첫 실행 때 현재 패치를 보내지 않기

```yaml
SEND_ON_FIRST_RUN: "false"
```

### 한 번의 패치에서 보낼 최대 메시지 수

```yaml
MAX_MESSAGES: "8"
```

패치가 매우 길면 최대 메시지 수 이후 내용은 원문 링크로 대체합니다.

## 주의사항

- 웹후크 URL이 노출되면 디스코드에서 기존 웹후크를 삭제하고 새로 만드세요.
- 블리자드가 페이지 HTML 구조를 크게 바꾸면 `monitor.py`의 파싱 부분을 수정해야 할 수 있습니다.
- GitHub Actions 예약 실행은 정확히 초 단위로 실행되는 서비스가 아니므로 다소 늦게 시작될 수 있습니다.
