# 오버워치 패치 노트 → 디스코드 자동 알림

넥슨과 블리자드의 공식 패치 노트를 확인하고, 넥슨 한국어 패치를 우선 사용합니다. 같은 날짜와 원문 내용(수치·조건 포함)이 일치하는 패치는 넥슨 URL을 사용하고, 확인되지 않은 패치는 실제 수집한 Blizzard URL을 유지합니다. GitHub Actions에서 15분 간격으로 실행하도록 예약되어 있어 개인 PC를 켜둘 필요가 없습니다.

- 넥슨 목록의 페이지 데이터와 게시물 본문에서 패치를 수집합니다.
- 수동·예약 실행 모두 최신 패치 1개만 처리하며, 한국어로 확인되면 제목, 공식 링크, 본문, 자동 요약 카드를 Discord 웹훅으로 보냅니다.
- 패치 본문의 공식 이미지와 이미지 목록 메시지는 전송하지 않습니다. 원문 이미지만 변경돼도 본문이나 요약 카드를 다시 보내지 않습니다.
- 영문 패치는 `한국어 대기`로 기록하고, 한국어 본문이 올라오면 전송합니다. 한국어 페이지 주소여도 본문이 영어면 전송하지 않습니다.
- 처리 대상으로 선택된 최신 패치의 내용이 바뀌면 저장된 Discord 메시지 ID로 기존 메시지를 수정합니다.
- 전송 완료(`sent`) 기록에 원문 메시지 ID가 없으면 본문이나 카드 버전이 바뀌어도 자동 재전송과 요약 카드 추가를 차단합니다.
- 원문 메시지 ID가 있는 최신 패치는 본문에 변경이 없어도 누락되거나 오래된 요약 카드를 갱신합니다. 이미 보낸 원문은 요약 카드 처리 실패 때문에 다시 보내지 않도록 전송 진행 상황을 저장합니다.
- `state.json`에 본문 해시, 메시지 ID, 요약 카드 상태를 저장해 중복을 방지합니다. 실행 도중 오류가 나더라도 저장된 진행 상황을 GitHub에 반영하고, 실행 결과는 실패로 표시합니다.

## 1. 디스코드 웹훅 만들기

1. 알림을 받을 Discord 서버에서 원하는 텍스트 채널을 엽니다.
2. `채널 편집 → 연동 → 웹후크 → 새 웹후크`로 이동합니다.
3. 이름과 채널을 정한 뒤 `웹후크 URL 복사`를 누릅니다.
4. 웹후크 URL은 비밀번호처럼 취급하며 다른 사람에게 공개하지 않습니다.

## 2. GitHub 저장소 준비

이 폴더 안의 파일을 GitHub 저장소에 올립니다. 공개 저장소로 만들어도 되지만 웹후크 주소는 코드에 직접 넣지 않습니다.

필수 구조:

```text
.github/workflows/check-patch.yml
monitor.py
balance_context.py
summary_text.py
summary_cards.py
requirements.txt
state.json
```

실제로 실행되는 워크플로는 `.github/workflows/check-patch.yml`입니다. 최상단의 `check-patch.yml`은 같은 내용의 참고용 복사본이며, 설정을 바꿀 때 두 파일을 함께 수정합니다.

## 3. 웹훅 주소를 GitHub 비밀값으로 등록

저장소에서 `Settings → Secrets and variables → Actions → New repository secret`로 이동합니다.

- Name: `DISCORD_WEBHOOK_URL`
- Secret: 앞에서 복사한 Discord 웹후크 URL

## 4. 실행

1. 저장소의 `Actions` 탭을 엽니다.
2. `Overwatch patch monitor`를 선택합니다.
3. `Run workflow`를 눌러 수동 실행합니다.
4. 실행 로그에서 수집 출처와 전송·수정·한국어 대기 결과를 확인합니다.

**`Overwatch patch monitor`는 수동 `Run workflow`와 예약 실행 모두 가장 최근 패치 1개만 처리합니다.** 가장 최신 날짜에 넥슨 게시물이 있으면 넥슨을 우선하고, 선택한 출처의 같은 날짜 게시물 중 가장 나중 게시물 하나를 고릅니다. 과거 패치의 본문 전송·수정·요약 카드 갱신은 수행하지 않습니다. 선택된 최신 패치의 본문과 카드가 이미 최신이면 중복으로 보내지 않습니다. 선택된 글이 영어이면 한국어판을 기다리며 이전 패치를 대신 보내지 않습니다. 패치 하나의 본문이나 카드는 길이에 따라 여러 Discord 메시지로 나뉠 수 있습니다.

수집·출처 중복 확인·기존 상태 이관·첫 실행의 과거 기준선 기록에는 전체 수집 목록을 사용하지만, 실제 전송·수정·요약 카드 갱신과 `DRY_RUN` 미리보기는 최신 패치 1개로 제한합니다. 이 제한은 코드에서 항상 적용하며 환경 변수로 해제할 수 없습니다.

새로운 상태 파일로 처음 실행하면 `SEND_ON_FIRST_RUN=true`일 때 선택된 최신 패치 1개를 한국어 확인 후 전송합니다. `false`이면 수집된 패치를 기준선으로 기록하고 전송하지 않습니다. 예약 실행은 매시 7, 22, 37, 52분에 확인하도록 설정되어 있습니다. 예약 시각은 실행 시각을 보장하지 않으며, GitHub Actions 상황에 따라 지연되거나 누락될 수 있습니다. [GitHub 예약 실행 안내](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

기존 `state.json`을 유지한 채 수정 버전을 처음 실행하면, 원문 메시지 ID가 있는 최신 패치의 누락되거나 오래된 요약 카드가 갱신될 수 있습니다. 전송 완료(`sent`) 기록에 원문 메시지 ID가 없으면 대체 메시지나 요약 카드를 자동으로 보내지 않습니다. 영어 본문은 계속 한국어판을 기다립니다. **문제 해결을 위해 `state.json`을 삭제하지 마세요.** 전송 이력이 없어지면 중복 메시지가 생길 수 있습니다.

## 자동 요약 카드 형식

- 분류는 외부 AI API 없이 로컬 규칙으로 처리하므로 AI API 키나 호출 비용이 필요하지 않습니다. `balance_context.py`는 공식 패치로 확인한 모드·영웅·기술별 수치의 이득 방향을 보완합니다. 등록되지 않은 기술이나 불명확한 변경도 사용자 확인 없이 변경 사항 카드로 자동 발송합니다.
- **원문 전체 → 일반 모드 카드 → 스타디움 카드** 순서로 전송합니다. 원문은 메시지 개수 제한 없이 나누어 끝까지 보내며, 개발자 설명·수치·단위·조건을 유지합니다.
- 각 모드에서 **상향 → 하향 → 조정**, 각 유형 안에서 **돌격 → 공격 → 지원** 순서입니다. 한 장에는 하나의 모드·유형·역할군만 들어가고, 같은 그룹의 여러 장은 연속으로 출력합니다. 빈 카드는 만들지 않습니다.
- 본문 **36px**, 영웅명 **38px**, 역할 제목 **40px**, 유형 제목 **64px**, 줄 높이 **52px**입니다. 변경 항목 간 12px, 영웅 사이 22px를 더 띄웁니다. 글자를 줄이지 않고 최대 1,400px 높이에서 다음 카드로 이어갑니다.
- `방어력이 325에서 275로 감소했습니다. (5대5)`는 `방어력 325 → 275 (5대5)`로 표시하고 바뀐 값을 강조합니다.
- 같은 모드의 한 영웅에게 확인된 상향만 있으면 상향, 하향만 있으면 하향, 둘 다 있으면 조정입니다. 조정 안에서도 각 변경의 ↑/↓를 유지합니다. 일반 모드와 스타디움의 판정은 독립적입니다.
- 특전 변경은 수치의 증가·감소와 관계없이 항상 **조정(↔)**으로 분류합니다. 같은 모드·영웅에 특전 변경이 포함되면 확인된 변경 묶음도 조정으로 표시합니다.
- 근거가 부족한 항목은 원문 문장을 그대로 **변경 사항** 별도 카드에 남기고 `•`로 표시합니다. 확인된 수치 변경과 분리하며 임의로 조정에 넣지 않습니다. 변경 사항·기타 변경 카드는 모든 일반/스타디움 분류 카드 뒤에 모드와 역할을 나누어 자동 발송하며, 수동 판정을 기다리지 않습니다.
- 시각·음향·UI·조준선 같은 표현 변경은 회색 점으로 남기며 전투 변경의 방향을 뒤집지 않습니다. 표현 변경만 있으면 기타 변경 카드입니다. 개발자 설명은 원문 메시지에서 읽을 수 있습니다.
- 역할은 해당 원문의 제목을 우선하며, 생략된 경우 수집한 다른 공식 글에 명시된 영웅 역할을 참조합니다. 확인할 수 없으면 별도의 역할 확인 필요 카드로 표시합니다.
- 현재 카드 버전은 **6**(`SUMMARY_CARD_VERSION`)입니다. 원문 메시지 ID가 있는 최신 패치의 구버전 카드를 갱신하며, 원문 형식이 구버전이면 원문 전체도 한 번 복구합니다. 본문 갱신 시 기존 카드 블록을 정리하고 원문 처리 후 카드를 다시 만들어 원문 뒤에 배치합니다. 단계별 메시지 ID를 저장해 실패 후 이어갑니다. 본문과 카드가 최신이면 중복 전송하지 않습니다.
- 같은 패치인지 확인할 때 날짜와 전체 내용의 수치·단위·조건을 비교합니다. 날짜만 같거나 숫자를 지운 문장이 비슷하다는 이유로 다른 패치를 합치거나 링크를 바꾸지 않습니다.

분류 기준은 `prompts/balance-classification.md`, 표기 기준은 `prompts/compact-summary-style.md`, 검증 계약은 `prompts/mobile-card-contract.md`에 있습니다. PR과 코드 브랜치의 `Monitor regression tests`가 실제 Discord 요청을 mock 처리한 회귀 테스트와 예시 렌더링을 실행합니다. `summary-card-previews` 아티팩트에서 실제 공식 글 기반 PNG와 `manifest.json`을 확인할 수 있습니다.

## 로컬 확인 및 테스트

Python 3.12 환경에서 라이브러리를 설치하고 오프라인 회귀 테스트를 실행합니다.

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

실제 사이트 수집 결과는 `DRY_RUN=true`로 확인합니다. 이 모드에서는 웹훅 주소 없이 실행할 수 있으며, Discord 요청과 `state.json` 저장 없이 수집 결과 및 처리 예정 동작을 출력합니다. 사이트를 가져오기 위한 인터넷 연결은 필요합니다.

PowerShell:

```powershell
$env:DRY_RUN = "true"
python monitor.py
Remove-Item Env:DRY_RUN
```

macOS / Linux:

```sh
DRY_RUN=true python monitor.py
```

## 설정 변경

`.github/workflows/check-patch.yml`의 `env`에서 바꿀 수 있습니다.

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| `SEND_ON_FIRST_RUN` | `"true"` | 새 상태 파일의 첫 실행에서 선택된 최신 패치 1개를 한국어 확인 후 전송합니다. `"false"`면 수집된 패치를 기준선으로 기록만 합니다. |
| `NEXON_MAX_ARTICLES` | `"20"` | 넥슨 목록에서 상세 확인할 최근 게시물 수입니다. |
| `MONTH_LOOKBACK` | `"4"` | 블리자드에서 현재 달을 포함해 최근 4개월을 확인합니다. |
| `DRY_RUN` | `"false"` | `"true"`면 Discord 전송과 상태 파일 저장 없이 미리 확인합니다. |
| `LATEST_PATCH_ONLY` | 워크플로에 `"true"`로 명시 | 현재 코드는 이 환경 변수를 읽지 않고 항상 최신 패치 1개만 처리합니다. `"false"`로 바꾸거나 생략해도 과거 패치 처리를 활성화할 수 없습니다. |

확인 주기는 워크플로의 `schedule`에서 바꿉니다. 현재 설정은 UTC 기준으로 매시 7, 22, 37, 52분입니다.

```yaml
- cron: "7,22,37,52 * * * *"
```

## 문제 확인

- `새로 전송: 0`이어도 오류는 아닐 수 있습니다. 이미 보낸 패치인지, `한국어 대기`인지 로그를 함께 확인합니다.
- 사이트 구조가 바뀌거나 수집이 실패하면 실행 로그의 수집 오류를 확인합니다.
- Discord 전송 오류가 나면 성공한 부분의 상태가 저장됩니다. 다음 실행에서 미완료 작업을 다시 처리합니다.
- Discord가 요청 제한(429)을 반환하면 `retry_after` 또는 `Retry-After`의 대기 시간을 지켜 최대 4회 재시도합니다. 업로드 파일은 매번 처음부터 읽습니다. 연결 실패처럼 전송 여부가 불확실한 오류를 즉시 재전송하지 않습니다.
- `state.json 저장` 단계가 실패하면 저장소 쓰기 권한이나 원격 변경과의 충돌을 확인합니다. 강제 푸시로 덮어쓰지 않습니다.
- 요약 카드의 한글을 표시하려면 한글 폰트가 필요합니다. GitHub Actions는 `fonts-noto-cjk`를 설치합니다.
- 웹후크 URL이 노출되면 Discord에서 기존 웹후크를 삭제하고 새로 만드세요.
