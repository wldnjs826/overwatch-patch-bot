# 오버워치 패치 노트 → 디스코드 자동 알림

넥슨과 블리자드의 공식 패치 노트를 확인하고, 넥슨 한국어 패치를 우선 사용합니다. 블리자드는 넥슨보다 최신인 패치를 보조 추적하고, 넥슨 수집에 실패하면 대체 출처로 사용합니다. GitHub Actions에서 15분 간격으로 실행하도록 예약되어 있어 개인 PC를 켜둘 필요가 없습니다.

- 넥슨 목록의 페이지 데이터와 게시물 본문에서 패치를 수집합니다.
- 한국어로 확인된 새 패치의 제목, 공식 링크, 본문, 자동 요약 카드를 Discord 웹훅으로 보냅니다.
- 패치 본문의 공식 이미지와 이미지 목록 메시지는 전송하지 않습니다. 원문 이미지만 변경돼도 본문이나 요약 카드를 다시 보내지 않습니다.
- 영문 패치는 `한국어 대기`로 기록하고, 한국어 본문이 올라오면 전송합니다. 한국어 페이지 주소여도 본문이 영어면 전송하지 않습니다.
- 이미 보낸 패치의 내용이 바뀌면 저장된 Discord 메시지 ID로 기존 메시지를 수정합니다.
- 예전 기록에 메시지 ID가 없는 패치의 내용이 바뀌면 대체 메시지를 한 번 보내고 새 ID를 저장합니다. 기존 메시지는 ID를 알 수 없어 남아 있습니다.
- 본문에 변경이 없어도 누락된 요약 카드를 추가합니다. 이미 보낸 원문은 요약 카드 처리 실패 때문에 다시 보내지 않도록 전송 진행 상황을 저장합니다.
- `state.json`에 본문 해시, 메시지 ID, 요약 카드 상태를 저장해 중복을 방지합니다. 실행 도중 오류가 나더라도 저장된 진행 상황을 GitHub에 반영하고, 실행 결과는 실패로 표시합니다.

## 1. 디스코드 웹훅 만들기

1. 알림을 받을 Discord 서버에서 원하는 텍스트 채널을 엽니다.
2. `채널 편집 → 연동 → 웹후크 → 새 웹후크`로 이동합니다.
3. 이름과 채널을 정한 뒤 `웹후크 URL 복사`를 누릅니다.
4. 웹후크 URL은 비밀번호처럼 취급하며 다른 사람에게 공개하지 않습니다.

## 2. GitHub 저장소 준비

이 폴더 안의 파일을 GitHub 저장소에 올립니다. 공개 저장소로 만들어도 되지만 웹후크 주소는 코드에 직접 넣지 않습니다.

필수 구조:

```text
.github/workflows/check-patch.yml
monitor.py
summary_text.py
summary_cards.py
requirements.txt
state.json
```

실제로 실행되는 워크플로는 `.github/workflows/check-patch.yml`입니다. 최상단의 `check-patch.yml`은 같은 내용의 참고용 복사본이며, 설정을 바꿀 때 두 파일을 함께 수정합니다.

## 3. 웹훅 주소를 GitHub 비밀값으로 등록

저장소에서 `Settings → Secrets and variables → Actions → New repository secret`로 이동합니다.

- Name: `DISCORD_WEBHOOK_URL`
- Secret: 앞에서 복사한 Discord 웹후크 URL

## 4. 실행

1. 저장소의 `Actions` 탭을 엽니다.
2. `Overwatch patch monitor`를 선택합니다.
3. `Run workflow`를 눌러 수동 실행합니다.
4. 실행 로그에서 수집 출처와 전송·수정·한국어 대기 결과를 확인합니다.

**수동 `Run workflow`는 가장 최근 패치 1개만 처리합니다.** 같은 날 여러 패치가 있으면 가장 나중 게시물 하나를 고르며, 과거 패치의 본문 전송·수정·요약 카드 갱신은 수행하지 않습니다. 최신 패치가 이미 전송됐고 변경도 없으면 중복으로 보내지 않습니다. 최신 글이 영어이면 한국어판을 기다리며 이전 패치를 대신 보내지 않습니다. 패치 하나의 본문이나 카드는 길이에 따라 여러 Discord 메시지로 나뉠 수 있습니다.

예약 실행은 기존처럼 수집 범위 전체에서 새 패치와 미완료 갱신을 확인합니다.

새로운 상태 파일로 처음 실행하면 설정에 따라 가장 최신 날짜의 패치를 전송 대상으로 삼고, 한국어로 확인되면 전송합니다. 이후에는 매시 7, 22, 37, 52분에 확인하도록 예약됩니다. 예약 시각은 실행 시각을 보장하지 않으며, GitHub Actions 상황에 따라 지연되거나 누락될 수 있습니다. [GitHub 예약 실행 안내](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

기존 `state.json`을 유지한 채 수정 버전을 처음 실행하면, 처리 대상 패치의 누락된 요약 카드가 추가될 수 있습니다. 본문이 바뀌었는데 메시지 ID가 없는 과거 기록은 대체 메시지를 한 번 전송합니다. 영어 본문은 계속 한국어 대기 상태로 남습니다. **문제 해결을 위해 `state.json`을 삭제하지 마세요.** 전송 이력이 없어지면 중복 메시지가 생길 수 있습니다.

## 자동 요약 카드 형식

- 상향(민트), 하향(분홍), 조정(주황) 카드에서 역할군과 영웅별로 변경을 묶습니다. 역할군이 원문에 없으면 `영웅`으로 표시합니다.
- `방어력이 325에서 275로 감소했습니다. (5대5)`는 `방어력 325 → 275 (5대5)`로, `궁극기 비용이 6% 감소했습니다.`는 `궁극기 비용 -6%`로 표시합니다. 바뀐 값은 색으로 강조합니다.
- 한 영웅에 상향·하향이 함께 있으면 조정 카드에 묶고 각 항목에 `↑`/`↓`를 표시합니다. 판단이 모호한 변경은 `↔`로 남깁니다. 시각·음향 같은 표현 변경은 회색 `•`로 표시하며 전투 수치의 상향·하향 분류를 뒤집지 않습니다.
- 개발자 설명은 원문 메시지에 유지하되 카드의 변경 항목에서는 제외합니다. 일반전과 스타디움의 같은 영웅을 합치지 않으며, 스타디움 항목은 이름표에 모드를 표시합니다.
- 기술명, 특전, 모드 조건, 단위를 보존하며 긴 영웅 변경 목록은 다음 카드로 이어집니다. 짧은 카드는 내용 높이에 맞춰 줄어듭니다.
- 카드 버전 3을 처음 실행하면 본문이 같아도 기존 요약 카드를 보완된 분류로 갱신합니다. 저장된 메시지 ID가 있으면 **예전 카드 메시지의 이미지를 수정**하므로 채널 맨 아래에 새 메시지가 생기지 않을 수 있습니다. 이후 동일한 패치는 다시 수정하지 않습니다.

분류 기준은 `prompts/balance-classification.md`에 정리했습니다. 피해·생명력·재생률·사거리 같은 이득 수치는 증가하면 상향, 재사용 대기시간·비용·공격 동작 시간 같은 부담 수치는 감소하면 상향입니다. 비용 자체와 비용의 감소량을 구분하고, 지속 시간은 기술의 맥락을 확인합니다.

표기 규칙은 `prompts/compact-summary-style.md`에 있습니다. PR과 코드 브랜치에서 실행되는 `Monitor regression tests`는 Discord 비밀값 없이 테스트와 예시 렌더링을 수행합니다. 실행 결과의 `summary-card-previews` 아티팩트에서 상향·조정·긴 목록·일반 변경 예시 PNG와 변환 내용을 담은 `manifest.json`을 확인할 수 있습니다. 예시의 수치는 형식 검증용입니다.

## 로컬 확인 및 테스트

Python 3.12 환경에서 라이브러리를 설치하고 오프라인 회귀 테스트를 실행합니다.

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

실제 사이트 수집 결과는 `DRY_RUN=true`로 확인합니다. 이 모드에서는 웹훅 주소 없이 실행할 수 있으며, Discord 요청과 `state.json` 저장 없이 수집 결과 및 처리 예정 동작을 출력합니다. 사이트를 가져오기 위한 인터넷 연결은 필요합니다.

PowerShell:

```powershell
$env:DRY_RUN = "true"
python monitor.py
Remove-Item Env:DRY_RUN
```

macOS / Linux:

```sh
DRY_RUN=true python monitor.py
```

## 설정 변경

`.github/workflows/check-patch.yml`의 `env`에서 바꿀 수 있습니다.

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| `SEND_ON_FIRST_RUN` | `"true"` | 새 상태 파일의 첫 실행에서 최신 날짜의 패치를 한국어 확인 후 전송합니다. `"false"`면 기존 패치를 기록만 합니다. |
| `NEXON_MAX_ARTICLES` | `"20"` | 넥슨 목록에서 상세 확인할 최근 게시물 수입니다. |
| `MONTH_LOOKBACK` | `"4"` | 블리자드에서 현재 달을 포함해 최근 4개월을 확인합니다. |
| `MAX_TEXT_MESSAGES` | `"20"` | 패치 하나에 보낼 원문 텍스트 메시지의 최대 개수입니다. 자동 요약 카드에는 적용하지 않습니다. |
| `DRY_RUN` | `"false"` | `"true"`면 Discord 전송과 상태 파일 저장 없이 미리 확인합니다. |
| `LATEST_PATCH_ONLY` | 수동 실행 `"true"`, 그 외 `"false"` | 최신 패치 한 개의 본문·카드만 처리합니다. 로컬에서도 `"true"`로 설정할 수 있습니다. |

확인 주기는 워크플로의 `schedule`에서 바꿉니다. 현재 설정은 UTC 기준으로 매시 7, 22, 37, 52분입니다.

```yaml
- cron: "7,22,37,52 * * * *"
```

## 문제 확인

- `새로 전송: 0`이어도 오류는 아닐 수 있습니다. 이미 보낸 패치인지, `한국어 대기`인지 로그를 함께 확인합니다.
- 사이트 구조가 바뀌거나 수집이 실패하면 실행 로그의 수집 오류를 확인합니다.
- Discord 전송 오류가 나면 성공한 부분의 상태가 저장됩니다. 다음 실행에서 미완료 작업을 다시 처리합니다.
- Discord가 요청 제한(429)을 반환하면 `retry_after` 또는 `Retry-After`의 대기 시간을 지켜 최대 4회 재시도합니다. 업로드 파일은 매번 처음부터 읽습니다. 연결 실패처럼 전송 여부가 불확실한 오류를 즉시 재전송하지 않습니다.
- `state.json 저장` 단계가 실패하면 저장소 쓰기 권한이나 원격 변경과의 충돌을 확인합니다. 강제 푸시로 덮어쓰지 않습니다.
- 요약 카드의 한글을 표시하려면 한글 폰트가 필요합니다. GitHub Actions는 `fonts-noto-cjk`를 설치합니다.
- 웹후크 URL이 노출되면 Discord에서 기존 웹후크를 삭제하고 새로 만드세요.
