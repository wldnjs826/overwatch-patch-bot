# 작업 하네스: 공식 이미지 전송 제외

기준 지침: 사용자가 제공한 [engineering-harness.md](engineering-harness.md). 이 문서는 해당 지침에 따른 작업별 수용 기준과 실행 기록이다.

## 사용자 요청

1. Discord 패치 알림에서 패치 본문의 공식 이미지를 보내지 않는다.
2. 자동 요약 카드의 출력 형식 선택안을 여러 개 제시한다. 사용자가 선택하기 전에는 카드 형식을 바꾸지 않는다.
3. 목표, 제약, 수용 기준을 명시한 이 프롬프트에 따라 구현하고 검증한다.

## 구현 범위와 제약

- 제목, 한국어 패치 본문, 공식 출처 링크, 자동 생성 요약 카드는 유지한다.
- 원문 이미지용 Discord embed 메시지와 이미지 목록 문구는 생성하지 않는다.
- 원문 이미지만 바뀌면 본문 재전송이나 카드 재생성을 하지 않는다.
- 기존 state.json을 읽을 수 있어야 하며 전송 이력을 초기화하지 않는다.
- 이미 게시된 메시지를 일괄 삭제하지 않는다. 본문 수정 시 기존 메시지 묶음을 갱신하는 동작은 유지한다.
- 실제 Discord 요청은 모의 객체로 대체해 검증한다.
- 테스트는 GitHub Actions의 격리된 Ubuntu 러너에서 Python 3.12로 실행한다. 로컬 호스트에서는 코드 탐색과 파일 편집, Git 작업만 수행한다.

## 수용 기준

1. 이미지가 포함된 신규 패치도 본문과 자동 요약 카드만 전송한다.
2. 원문 이미지 URL이 전송 payload에 들어가지 않는다.
3. 본문이 같고 원문 이미지만 달라지면 추가 Discord 요청이 없다.
4. 본문이 바뀌면 수정 메시지와 요약 카드가 정상 갱신된다.
5. DRY_RUN 판정도 실제 전송 조건과 일치한다.
6. 기존 회귀 테스트 및 위 동작의 회귀 테스트가 통과한다.

## 실행 순서

현재 main 확인 → 전송 및 변경 감지 수정 → 회귀 테스트 → 별도 검토 → 수정 PR과 카드 선택안 제시.

기준 코드: `0093e73` (`main` 확인 시점). 운영 중 갱신되는 `state.json`은 변경하지 않는다.

## 카드 선택안 작성 기준

비교할 수 있도록 각 안의 배치, 예시, 적합한 용도를 설명한다. Discord 모바일에서 읽기 쉬운 안을 권장한다. 선택안은 제안이며 구현된 형식으로 표현하지 않는다.
