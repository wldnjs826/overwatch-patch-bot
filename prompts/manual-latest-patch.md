# 수동·예약 실행은 최신 패치 한 개만 처리

- 과거 패치의 대량 전송을 막기 위해 Actions의 수동 Run workflow와 예약 실행 모두 최신 패치 하나만 처리한다.
- 두 check-patch.yml 파일은 `LATEST_PATCH_ONLY: "true"`를 명시하지만, 현재 코드는 이 환경 변수를 읽지 않고 최신 한 개 제한을 항상 적용한다. 환경 변수를 false로 지정하거나 `select_delivery_patches(..., False)`로 호출해도 제한을 해제하지 않는다.
- 수집·출처 중복 제거·동일 날짜 순서 ID 부여는 전체 목록에서 완료한다. 가장 최신 날짜에 넥슨 게시물이 있으면 넥슨을 우선하고, 선택한 출처의 같은 날짜 게시물 중 순서가 가장 큰 하나만 실제 전송/수정/요약 카드 갱신 및 DRY_RUN 대상으로 선택한다.
- 기존 상태 이관 및 첫 실행의 과거 기준선 기록에는 전체 목록을 유지한다. 최신 한 개 제한 때문에 과거 기록을 잃지 않게 한다.
- 최신 패치가 이미 전송됐으면 중복 전송하지 않으며 영어이면 한국어판을 기다린다. 오래된 글로 대체하지 않는다. 패치 한 개가 Discord 메시지 한 개라는 의미는 아니다.
- 전송 완료(`sent`) 기록에 원문 메시지 ID가 없으면 본문이나 카드 버전이 달라져도 자동 재전송과 요약 카드 추가를 차단한다. 운영 state.json을 초기화하지 않는다.
- `engineering-harness.md`에 따라 GitHub Actions의 격리된 Ubuntu runner에서 전체 테스트를 수행한다. tests/test_manual_scope.py에서 실제 main/process_patch 흐름을 확인하며 Discord 전송과 수집은 mock으로 차단한다.
