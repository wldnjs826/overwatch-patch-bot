# 모바일 패치 카드 구현·검증 계약

사용자의 2026-09-22 요구사항을 적용한다. engineering-harness.md 원문은 변경하지 않는다.

## 출력 계약

1. 원문은 공식 출처 URL과 모든 문장을 먼저 출력한다. 메시지 개수나 번호 접두어 때문에 자르지 않는다.
2. 출처는 확인한 넥슨 공식 공지 URL을 사용한다. 기존 다른 출처의 전송 이력은 날짜와 본문이 정확히 일치할 때만 메시지 ID를 이어받는다.
3. 일반전의 상향/하향/조정 각각 돌격/공격/지원 카드가 끝난 뒤 스타디움도 동일 순서로 출력한다.
4. 한 장에는 하나의 모드, 변경 유형, 역할군만 포함한다. 같은 그룹의 여러 장은 연속이며 빈 카드는 없다.
   일반 기술과 특전 모두 실제 효과를 판정한다. 같은 모드·영웅에 확인된 상향과 하향이 함께 있을 때만 조정이다. 특전이라는 이유만으로 조정에 넣지 않는다.
5. 근거가 부족한 문장은 변경 사항 부록에 원문 그대로 표시한다. 확인된 변경만 해당 전투 분류에 들어간다. 표현 변경만 있으면 기타 변경 부록이다. 부록도 모드·역할을 분리하고 모든 분류 카드 뒤에 둔다.
6. 본문 36px, 영웅명 38px, 역할 40px, 제목 64px을 고정한다. 내용이 길면 추가 페이지를 사용한다.
7. 최초 새 패치는 전체 원문 뒤에 전체 카드를 전송한다. 이후 수정은 기존 원문을 편집하고 바뀐 항목만 별도 수정 사항 카드로 보낸다. 기존 전체 카드 블록을 삭제·재생성하지 않는다. 추가·수정·원문 삭제를 구분하고 수정 항목에는 이전 표기도 남긴다. 미완료 수정의 원문·행·메시지 ID를 저장하여 중단 후 이어간다.
8. 카드 버전 변경과 단순 순서·공백 변경만으로 전체 카드를 다시 보내지 않는다. 예전 원문 스냅샷이 없고 본문이 바뀌었으면 기존 Discord 원문을 읽어 비교하며, 복구 실패 시 전체 재게시로 대체하지 않는다.

## 증거와 검증

- tests/test_output_contract.py: 원문 20개 메시지 초과, 긴 문단, 숫자·조건, 링크, 실제 레이아웃의 전송 순서, 중단 후 복구.
- tests/test_patch_revisions.py: 변경 항목만 추출, 특전 이름표 수정, 모드 독립 비교, 추가/삭제, 기존 카드 보존, 원문 복구, 재시도와 새 수정이 겹친 경우.
- tests/test_card_layout.py: 18개 분류 그룹, 역할/모드 격리, 고정 폰트, 페이지 넘침, 긴 변경문 보존, 빈 카드 제외.
- tests/test_summary.py: 수치의 이득/부담 판정, 모드별 독립 집계, 미판정 원문 보존, 실제 공식 패치 fixture.
- tests/test_manual_scope.py: 수동·예약 실행과 DRY_RUN의 최신 한 패치 범위 유지, `LATEST_PATCH_ONLY=false`로 과거 대량 전송을 활성화할 수 없음을 검증.
- GitHub Actions 격리 Ubuntu runner에서 테스트와 렌더링한다. 로컬에서는 코드·결과를 읽고 검토하며 실제 Discord로 테스트 메시지를 보내지 않는다.
