# 모바일 패치 카드 구현·검증 계약

사용자의 2026-09-22 요구사항을 적용한다. engineering-harness.md 원문은 변경하지 않는다.

## 출력 계약

1. 원문은 공식 출처 URL과 모든 문장을 먼저 출력한다. 메시지 개수나 번호 접두어 때문에 자르지 않는다.
2. 동일 날짜·전체 내용의 수치와 조건까지 확인된 경우 Nexon을 우선한다. 미확인 패치에는 실제 수집한 Blizzard 링크를 유지한다.
3. 일반전의 상향/하향/조정 각각 돌격/공격/지원 카드가 끝난 뒤 스타디움도 동일 순서로 출력한다.
4. 한 장에는 하나의 모드, 변경 유형, 역할군만 포함한다. 같은 그룹의 여러 장은 연속이며 빈 카드는 없다.
5. 근거가 부족한 문장은 판별 필요 부록에 원문 그대로 표시한다. 확인된 변경만 해당 전투 분류에 들어간다. 표현 변경만 있으면 기타 변경 부록이다. 부록도 모드·역할을 분리하고 모든 분류 카드 뒤에 둔다.
6. 본문 36px, 영웅명 38px, 역할 40px, 제목 64px을 고정한다. 내용이 길면 추가 페이지를 사용한다.
7. 원문이 길어지거나 삭제된 메시지를 복구하는 경우에도 카드가 원문보다 앞에 남지 않도록 기존 카드 블록을 재생성한다. 매번 성공 응답을 받은 ID를 저장한다.

## 증거와 검증

- tests/test_output_contract.py: 원문 20개 메시지 초과, 긴 문단, 숫자·조건, 링크, 실제 레이아웃의 전송 순서, 중단 후 복구.
- tests/test_card_layout.py: 18개 분류 그룹, 역할/모드 격리, 고정 폰트, 페이지 넘침, 긴 변경문 보존, 빈 카드 제외.
- tests/test_summary.py: 수치의 이득/부담 판정, 모드별 독립 집계, 미판정 원문 보존, 실제 공식 패치 fixture.
- tests/test_manual_scope.py: 수동 실행 최신 한 패치 범위 유지.
- GitHub Actions 격리 Ubuntu runner에서 테스트와 렌더링한다. 로컬에서는 코드·결과를 읽고 검토하며 실제 Discord로 테스트 메시지를 보내지 않는다.
