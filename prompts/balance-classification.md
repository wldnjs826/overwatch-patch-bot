# 자동 요약의 상향·하향 분류 기준

## 실제 원문에서 확인된 문제

- 2026-07-15 공식 글의 `.PatchNotes-dev` 문단에는 `개발자의 의견:` 접두사가 없다. 단순 키워드 검색으로 설명까지 변경 목록에 넣으면 상향·하향이 불분명해진다.
- 같은 글에서 정커퀸의 일반전 재사용 대기시간 감소와 스타디움 파워 공격력 감소가 하나의 영웅에 합쳐졌다. 모드별로 추출하고 스타디움 이름표를 표시해야 한다.
- 재생률, 배치 거리, 투사체 크기 등 실제 수치 항목이 사전에 없었다. `사거리 증가가 75%에서 40%로 감소`처럼 수치 항목 자체에 증가/감소가 들어가는 문장도 잘못 조정으로 취급했다.
- 시각·음향 변경 하나 때문에 명확한 전투 수치 변경까지 조정으로 바뀌었다.

## 판단 순서

1. 개발자 설명은 카드 분류에서 제외하되 원문에는 유지한다. 일반전/스타디움별로 영웅을 구분한다.
2. 실제 변경 항목의 전후 값 또는 증감 표현을 확인한다. 기술 이름 속 `강화` 같은 단어는 분류 근거가 아니다.
3. 피해·공격력·생명력·방어력·치유·재생률·사거리·배치/획득 거리·투사체 속도/크기·탄약 등은 증가가 상향이다.
4. 재사용 대기시간·궁극기 비용·소모량·시전/회복/지연/재장전 시간·공격 동작/변신 시간·분산도 등은 감소가 상향이다.
5. 재사용 대기시간/궁극기 비용의 **감소량**이 늘어나는 경우는 상향이다. 비용 자체와 구별한다.
6. 방벽·무적·드론 같은 유익한 효과의 지속 시간은 길어지면 상향이다. 공격 동작의 지속 시간은 짧아지면 상향이다. 맥락이 불명확한 지속 시간은 조정으로 남긴다.
7. 시각·음향 등 표현 변경은 회색 점으로 유지하고 영웅의 전투 분류에 합산하지 않는다.
8. 부정문, 단위가 달라 직접 비교할 수 없는 수치, 상반된 복합 변경, 알려지지 않은 수치 항목은 조정으로 둔다. 분류율을 높이려고 방향을 추측하지 않는다.
9. 한 모드의 영웅 변경이 모두 상향이면 상향, 모두 하향이면 하향으로 묶는다. 혼합되거나 미판정 전투 변경이 있으면 조정 카드에 묶고 각 항목의 방향을 표시한다.

## 검증과 재전송

- 실제 2026-07-15와 2026-09-09 공식 글의 본문 HTML을 테스트 fixture로 보존한다. 출처는 각 fixture 첫 줄에 있다.
- 실제 일반전 영웅별 기대 분류, 모드 분리, 개발자 설명 제외와 원문 보존을 테스트한다. 예시 PNG와 manifest도 이 fixture에서 생성한다.
- `engineering-harness.md`에 따라 테스트와 렌더링은 격리된 GitHub Actions Ubuntu runner에서만 수행한다. 실제 Discord 요청은 mock 처리한다.
- 카드 버전 3으로 갱신해 기존 카드도 수정한다. 429 응답은 [Discord 공식 문서](https://docs.discord.com/developers/topics/rate-limits)에 따라 서버 대기 시간을 따른 뒤 재시도한다. 요청이 거절된 경우에만 자동 재시도하고, 확인된 메시지 ID와 상태를 유지한다.
